# CitySync backend

Node.js + Express (plain JavaScript, CommonJS) API that fuses several civic data feeds into one normalized event stream, with a global vs local (Amer, Jaipur) geo-filter. No API keys, no accounts.

## Run

Requires Node 18 or newer (uses the built-in `fetch`).

```bash
npm install
npm start
```

The API is now on http://localhost:3000. Try:

```bash
curl "http://localhost:3000/events"               # everything (global)
curl "http://localhost:3000/events?scope=local"   # within 15 km of Amer
curl "http://localhost:3000/health"
```

Both `PORT` and `USE_MOCK` are optional. To change them, copy `.env.example` to `.env` or set them in the shell.

## Offline / demo mode

```bash
# any OS, any shell
npm run start:mock

# macOS / Linux / Git Bash
USE_MOCK=true npm start

# Windows PowerShell
$env:USE_MOCK="true"; npm start

# Windows cmd
set USE_MOCK=true && npm start
```

Or put `USE_MOCK=true` in `.env`. In this mode the server serves only `events.json` and makes no network calls. The startup log confirms it: `[mode] USE_MOCK=true - serving events.json only`.

## Endpoints

### `GET /events?scope=global|local`

Returns a JSON array of normalized events, newest first. `scope` defaults to `global`. `local` keeps events within 15 km (haversine) of Amer (26.9855, 75.8513). Any other `scope` value gets a `400`.

### `GET /health`

```json
{ "status": "ok", "mode": "live", "feeds": { "usgs": "live", "weather": "live", "aq": "live", "amer": "sim" }, "count": 312 }
```

Feed status values:

| value  | meaning                                                          |
| ------ | ---------------------------------------------------------------- |
| `live` | real upstream answered                                           |
| `sim`  | generated by the built-in Amer simulator                         |
| `mock` | upstream failed (or `USE_MOCK=true`); slice served from `events.json` |
| `down` | upstream failed and `events.json` has nothing for that feed      |

## Event schema

Every feed normalizes into exactly this shape:

```js
{
  id: string,          // unique per event
  type: "earthquake" | "weather" | "air_quality" | "traffic" | "crowd" | "civic" | "event",
  title: string,
  lat: number,
  lng: number,
  timestamp: string,   // ISO 8601
  severity: number,    // 1 (info) .. 5 (critical)
  source: string,
  isSimulated: boolean,
  raw: object          // source-specific extras
}
```

## Feeds

| feed    | source                                                                 | kind                    | severity rule |
| ------- | ---------------------------------------------------------------------- | ----------------------- | ------------- |
| usgs    | USGS all-day GeoJSON (`earthquake.usgs.gov`)                           | real, worldwide         | magnitude: <3 → 2, 3–4 → 3, 4–5 → 4, ≥5 → 5 |
| weather | Open-Meteo forecast API, current conditions at Amer                    | real, one event         | max of weather code (clear/cloud 2, rain 3, thunderstorm 4) and heat (≥35 °C 3, ≥40 °C 4) |
| aq      | Open-Meteo Air Quality API, current US AQI at Amer                     | real, one event         | AQI ≤50 1, ≤100 2, ≤150 3, ≤200 4, else 5 |
| amer    | built-in generator: traffic, crowd, civic complaints, scheduled event  | **simulated**           | see `adapters/amerSim.js` |

Simulated events are always `isSimulated: true` with `source: "Simulated (Amer)"`.

## Failure handling

- Each feed is called with `Promise.allSettled`, a 6 s timeout, and its own try/catch. A non-200, timeout, network error, or unexpected payload logs a warning line and that feed is backfilled from `events.json`. The server never exits because of a feed.
- Backfilled events are never presented as real: they are forced to `isSimulated: true` and a real source name gets a `(mock)` suffix (for example `"USGS (mock)"`).
- Upstream answers are cached for 60 s (failures for 15 s) so a polling frontend does not hammer the public APIs. The simulator is not cached, so it varies on every request.
- The console logs the live/mock status of every feed whenever it changes.

## Mock file

`events.json` lives in the project root, next to `package.json` (the server resolves it from its own location, so the working directory does not matter; the startup log prints the exact path). It uses the same schema. Whatever the file says, its events are always served as `isSimulated: true` with a `(mock)` source suffix, so mock data never passes as live. Timestamps in it are static, so edit them if you want the offline demo to look fresh. Feed slices are matched by `type`: `earthquake` backs `usgs`, `weather` backs `weather`, `air_quality` backs `aq`, everything else backs `amer`.

## Layout

```
server.js              Express app, CORS, /events and /health
adapters/
  usgs.js              USGS earthquakes
  weather.js           Open-Meteo weather
  airQuality.js        Open-Meteo air quality
  amerSim.js           simulated Amer feed
lib/
  normalize.js         runs adapters, mock fallback, fuse + sort + scope
  geo.js               haversine, Amer constants, scatter helper
  event.js             event schema validation + builder
  mock.js              events.json loader (tags everything as simulated)
  cache.js             tiny TTL cache with in-flight dedupe
  http.js              fetch wrapper with timeout and readable errors
  time.js              Open-Meteo local-time to UTC ISO conversion
  config.js            env handling
events.json            mock data
```
